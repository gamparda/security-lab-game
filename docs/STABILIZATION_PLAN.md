## PR 1 · 저장 보호

대상: R1·R3·R4. `src/storage.js`, `src/app.js`, 엔진·브라우저 저장 검사.

- 기존 v1 원본을 보존하고 새 저장 키·형식으로 변환한다. 알 수 없는 버전이나 손상 데이터는 자동 삭제하지 않는다.
- 저장에 개정 번호를 넣고, 저장·초기화를 같은 Web Locks 잠금 안에서 직렬화한다. 잠금 안에서 읽은 개정과 현재 탭의 개정이 다르면 쓰기를 중단한다. 개정 비교와 `setItem`만 분리해서 넣는 방식은 동시 쓰기를 막지 못한다.
- 다른 탭의 변경을 감지해 최신 진행을 불러오도록 안내한다. 해시 계산 중에도 오래된 상태를 나중에 저장하지 않도록 한다.
- 전체 초기화도 개정을 증가시킨 새 상태로 기록한다. 키 삭제만으로 초기화를 처리하지 않는다.
- 저장 불가·충돌·정상 저장·해시 재시도 안내를 별도로 관리한다. 저장 성공 시 저장 실패 안내만 해제한다.
- 원본 백업을 먼저 확보하고, 잠금 미지원·백업 실패 환경에서는 자동 덮어쓰기를 제한한다. 진행 내보내기를 제공한다. IndexedDB 거래 기반 대안은 호환성 검사 결과에 따라 검토한다.

완료 기준: 오래된 탭이 최신 진행과 초기화 결과를 덮어쓰지 않음; 동시 저장도 한 순서로 처리됨; 변환 실패·저장 공간 부족 시 원본 유지; 저장 성공 뒤 실패 안내 해제; 해시 실패 안내는 유지; v1 완료·진행 중·복구 직후 저장 변환 통과.

## PR 2 · 시작 실패 복구와 오류 정보

대상: R2·R5. `index.html`, `src/bootstrap.js`, 서버 CSP, 브라우저 로딩 검사.

- 시작 파일이 로드되기 전부터 동작하는 최소 감시 코드를 HTML에 둔다. 정적 CSP 해시로 허용하고 `unsafe-inline`, `eval`, 사용자 입력 기반 요청을 허용하지 않는다. HTML·Python 서버·Node 서버·정적 내보내기의 정책 일치를 검사한다.
- 시작 스크립트는 8초 제한·자동 재시도 최대 1회, 게임 초기화는 30초 제한을 적용한다. 어떤 시작 단계가 실패해도 재시도 수단을 표시한다.
- 정상 준비 중에는 로딩 안내만 표시한다. CSS 적용과 진행 복원이 끝난 뒤 게임을 연다. 취소된 시도의 늦은 응답으로 게임을 열지 않는다.
- 브라우저 실패 화면에 단계·파일·오류 정보와 복사 버튼을 제공한다. 클립보드를 사용할 수 없으면 선택 가능한 텍스트를 제공한다. 저장 내용은 오류 정보에 넣지 않는다.
- 서버는 내장 파일을 먼저 준비하는 현재 방식을 유지한다. HTTP 응답 원문과 내장 HTML을 비교하는 실행 차단 검사는 다시 넣지 않는다.

완료 기준: 시작 파일 404·차단·무응답 모두 제한 시간 후 안내; 자동 복구 성공 시 수동 안내 없음; 수동 재시도 뒤 저장 유지; 늦은 응답에도 실패 상태 유지; PC·모바일 조건과 CSP 검사 통과.

## PR 3 · 실행과 진행 이동

대상: R6. `launcher.py`, 저장 내보내기·가져오기 화면, `tests/windows_launcher.ps1`.

- Windows에서 사용자별 단일 인스턴스를 운영한다. 같은 버전 재실행은 기존 게임을 열고, 다른 버전이 실행 중이면 종료 후 새 버전을 실행하도록 안내한다.
- 앱이 소유한 인스턴스인지 확인한 뒤 고정된 열기·포커스 요청만 전달한다. 다른 프로그램이 사용 중인 포트를 게임으로 간주하지 않는다.
- 마지막으로 사용한 게임 포트를 앱 설정으로 기억하고 포트 변경을 안내한다. 다른 포트의 localStorage를 자동으로 읽을 수 있다고 가정하지 않는다.
- 게임 전용 JSON 내보내기·가져오기를 제공한다. 128KiB 상한, 형식·단서·순서·완료 조건을 검증하고 현재 진행 백업 후 가져온다. 가져오기에서 코드나 임의 파일 내용을 실행하지 않는다.
- 기존 Windows 검사의 ‘두 실행창은 서로 다른 포트를 사용’ 조건을 단일 인스턴스 조건으로 교체한다. EXE만 있는 폴더, 한글·공백 경로, 다른 프로그램의 포트 점유, 버전 교체를 검사한다.

완료 기준: 같은 버전 재실행은 같은 게임으로 연결; 버전이 다른 실행창과 혼동하지 않음; 다른 프로그램은 재사용하지 않음; 포트가 달라도 내보낸 진행을 검증·복원할 수 있음; 잘못된 가져오기에도 기존 저장 유지.

## PR 4 · 구조와 안내 정리

대상: R7. `src/missions.js`, 엔진·저장·화면, 기존 저장 변환 검사.

- 미션 ID를 기준으로 단서·명령 예시·화면 문구를 한곳에 정의한다. 개수 4에 의존하는 루프와 레이아웃을 정의에서 계산한다.
- 미션별 상태·복원 검증을 분리하되 기존 완료 조건, 방어 후 재검증, 정상 서비스 유지 조건을 보존한다.
- 현재 부족한 근거와 다음 행동을 화면에서 확인할 수 있도록 한다. 터미널 출력과 저장 상태를 혼동하지 않도록 안내한다.
- 실제 브라우저·모바일·키보드·200% 확대·스크린리더 확인 후 입문자 3–5명 시연으로 막힌 행동을 기록한다.

완료 기준: 기존 미션과 v1/v2 저장 회귀 통과; 미션 정의 변경 시 누락을 자동 검출; 작은 화면과 키보드 조작 유지; 시연 결과를 근거로 문구 조정.

## 실행 순서와 게시 기준

PR 1 → PR 2 → PR 3 → PR 4 순서로 진행한다. 문제가 드러나는 회귀 검사를 먼저 추가하고 각 PR에서 해당 검사를 통과시킨다. PR 1의 진행 내보내기는 PR 3에서 가져오기와 연결한다.

각 코드 PR은 `npm run check`와 변경에 맞는 검사를 통과해야 한다. Windows 변경은 실제 EXE 실행창과 게임까지 확인한다. 게시 시 버전이 붙은 ZIP·단일 EXE·체크섬을 제공하고, ZIP 내부 EXE와 단일 다운로드의 바이트 일치를 확인한다.

저장 원본 보존과 시작 실패 복구가 확인된 뒤 미션 추가를 검토한다. 선택 암호 퍼즐은 이 안정화 작업 이후 범위다.
