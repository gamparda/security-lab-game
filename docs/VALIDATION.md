## 알려진 한계와 수동 검증 계획

- 첫 프로토타입이며 학습 분량과 난이도를 사용자 시연으로 다듬어야 합니다.
- 30–45분의 목표 플레이 시간과 교육 효과는 아직 검증하지 않았습니다.
- 시뮬레이션은 실제 HTTP·방화벽·인증 시스템의 세부 동작을 구현하지 않습니다.
- 로그인 정책의 길이 15·3회 제한은 이 게임에서 선택한 예시입니다. 실제 서비스의 모든 인증 구성에 일률 적용하는 권고가 아닙니다.
- localStorage는 같은 브라우저의 진행 정보이며 서버 동기화·공정한 점수 인증을 제공하지 않습니다.
- 내장 오프라인 기준을 신뢰하는 게임 상황입니다. 실제 파일 서명·기준 배포·키 관리는 구현하지 않았습니다.
- 기준값과 현재 해시는 실제 바이트에서 계산합니다. 개인 파일 업로드 기능은 없습니다.
- 스크린리더 및 실기기 수동 검증, 입문자 3–5명 시연은 후속 작업입니다.

수동 시연에서는 포트 전체 차단의 실패 이유와 해시 일치의 의미를 플레이어가 자신의 말로 설명하는지 기록합니다. 시연 체크리스트와 후속 우선순위는 `ROADMAP.md`를 참고합니다.

## 초기 로딩 준비 확인 · 2026-10-02

v0.2.0의 흰 화면 제보는 사용자 재실행 후 정상화됐습니다. 게시된 EXE에서 추출한 HTML·CSS·JS는 원본과 일치했고, 해당 자산을 Linux Chromium에서 localhost·127.0.0.1 각각 10회 로드해 스타일 적용을 확인했습니다. 사용자 PC에서 발생한 최초 실패의 원인은 재현·확정하지 못했습니다.

v0.2.1은 EXE가 모든 허용 게임 파일의 로컬 HTTP 응답·형식·내용을 확인한 뒤 브라우저를 열도록 합니다. 브라우저는 CSS의 실제 적용과 게임 모듈 초기화·진행 복원이 끝나기 전에는 게임을 숨깁니다. CSS 요청은 한 번 재시도하고, 단계별 8초 시간 초과나 실패 시 페이지 다시 불러오기를 안내합니다.

검증 명령: `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run check`.

검증 결과: 엔진 **32개**, 서버 **6개**, PC·모바일 브라우저 **42개**, 총 **80개 모두 통과**했습니다.

- 느린 CSS·게임 모듈은 로딩 안내를 유지하고, 준비 완료 후에만 게임 표시.
- 첫 CSS 실패의 자동 재시도, 재시도 실패와 정상 HTTP 응답의 잘못된 CSS 내용 차단.
- CSS·모듈 무응답의 시간 초과 안내, 늦게 도착한 응답만으로 게임을 다시 표시하지 않음.
- 의존 모듈 실패 안내, 수동 새로고침 후 정상 진행 유지와 초기화 완료.
- 서버 자산 준비 확인과 CSS 누락 시 시작 거부, 새 bootstrap 파일 제공.
- 기존 전체 플레이·저장·초기화·키보드·입력 경계 검증도 통과.

패키징된 Windows 실행 파일과 실행 창의 자산 준비 확인은 패치 릴리즈 워크플로의 게시 조건입니다.

v0.2.1은 Windows 검사에서 입력 테스트의 준비 대기 누락을 발견해 게시하지 않았습니다. 명령 입력 도우미가 입력 가능한 화면을 기다린 뒤 터미널 기록 수를 읽도록 수정했습니다. 검증을 통과한 패치는 v0.2.2로 배포합니다.

## 느린 준비·자동 복구와 배포 구성 수정 · 2026-10-03

v0.2.2의 EXE 내부 HTML·CSS·bootstrap·게임 모듈이 원본과 일치함을 확인했습니다. 기존 서버 자산 확인에서는 정상 응답을 2.2초 지연하면 단일 2초 제한으로 TimeoutError가 발생하는 경로를 재현했습니다. 서버가 첫 요청에 503을 반환하는 경우와 게임 의존 모듈의 첫 요청 실패도 주입해 복구를 확인했습니다. 사용자 PC의 원인이 같은지는 실행창/브라우저 오류 상세가 없어 확정하지 않았습니다.

서버 자산 확인은 실행창을 막지 않는 작업에서 최대 30초 재시도하고, 최종 실패해도 버튼으로 재검사할 수 있습니다. 브라우저는 게임 준비를 30초 기다리며 모듈 요청 실패는 페이지를 한 번만 다시 엽니다. 실제 준비가 완료되어야 게임을 표시하고 정상 저장을 유지합니다.

Linux 검사: 엔진 32개, 서버·배포 파일 11개, PC·모바일 브라우저 46개로 총 89개를 검증합니다. 8초 이상 느린 게임 준비, 첫 모듈 요청 실패 자동 복구, 지연·일시 실패 서버의 준비 확인, 취소·시간 초과, 가이드 제거 시 EXE 바이트 보존을 추가했습니다. Windows의 패키징된 EXE와 실행창 검증은 게시 전 워크플로에서 별도로 수행합니다.

릴리즈는 Windows ZIP과 SHA256SUMS.txt만 게시하며 ZIP에는 EXE만 포함합니다. 기존 릴리즈도 Windows ZIP의 기존 체크섬을 먼저 검증한 뒤 가이드만 제거하고 EXE 바이트 보존을 확인합니다. 바뀐 ZIP의 체크섬을 갱신하고 웹 ZIP 및 해당 안내를 제거합니다.

Windows v0.2.3 패키징 검사에서 PC·모바일 각각 한 번의 `page.reload: net::ERR_CONNECTION_REFUSED`를 발견해 게시하지 않았습니다. 이때 서버 프로세스는 계속 실행 중이었습니다. Python 3.12 HTTPServer의 기본 연결 대기열은 5개이며, 느린 accept 루프에 32개 파일 요청을 동시에 보내는 재현에서 26개가 실패했습니다. 같은 조건에서 대기열 64개는 32개 모두 성공했습니다. 실제 앱·소스 서버·smoke-test 경로가 모두 같은 GameServer를 사용하도록 수정하고 동시 요청 회귀 검사를 추가했습니다. 브라우저가 취소한 요청의 정상 연결 종료는 서버 오류 출력 없이 처리합니다. 수정 배포 버전은 v0.2.4이며, 검증 범위는 엔진 32개·서버/배포 12개·브라우저 46개, 총 90개입니다.
