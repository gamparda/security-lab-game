# 개발 계획

## 목표

보안을 처음 배우는 고등학생을 위한 가상 조사 게임. 튜토리얼과 필수 미션 3개, 목표 플레이 시간 30–45분. 개발 견적은 1인 주 5–7시간씩 6주이며, 프로그래밍 입문자는 준비 기간 2–4주를 추가합니다.

## 미션

| 미션 | 행동 | 완료 조건 |
| --- | --- | --- |
| 튜토리얼 · 5분 | help·inspect로 조사 범위 확인 | 단서와 허용 범위 확인 |
| 서비스 · 8–12분 | scan·설정 변경 | 불필요한 접근 차단, 필수 서비스 유지 |
| 로그인 · 8–12분 | 더미 후보·시도 기록 비교 | 차단 목록·시도 제한, 정상 로그인 확인 |
| 자료 · 8–12분 | 실제 SHA-256 비교·원본 복구 | 변경 확인, 복구 후 일치 검증 |
| 선택 암호 퍼즐 · 10분 | 시저 또는 반복 키 XOR | 복호화와 실사용 한계 설명 |

단서 조사 → 원인 설명 → 방어 → 정상 기능 재검증 → 해설. 실패하면 관찰한 사실과 다음 행동을 안내합니다.

## 화면과 점수

- 가상 터미널·방어 설정·파일 비교·전후 비교 탭, 목표·단서 패널.
- 작은 화면은 세로 배치. 성공·실패는 색상과 글자로 표시.
- 힌트: 개념 → 위치 → 행동. 힌트 감점 없음.
- 점수: 단서 30, 설명 20, 방어 30, 재검증 20. 완료에는 방어와 재검증이 필수.

## 구현 규칙

HTML·CSS·JavaScript, localStorage, localhost 정적 서버를 사용합니다. 해시는 Web Crypto로 계산합니다.

명령은 허용 목록으로 해석하고 최대 200자로 제한합니다. 사용자 IP·URL로 요청하거나 입력을 셸·eval·Function에 넘기지 않습니다. 출력은 textContent를 사용합니다. 개인 파일·실제 계정·비밀번호는 받지 않습니다.

열린 포트 자체는 취약점이 아닙니다. 길이뿐 아니라 흔한 값과 시도 제한을 확인합니다. 해시 불일치는 변경을 뜻하며 악성 여부·신원은 보장하지 않습니다. SHA-256을 비밀번호 저장용으로 사용하지 않습니다. 점수는 학습 피드백입니다.

## 일정과 검증

| 주차 | 작업 |
| --- | --- |
| 1 | 화면·명령·미션 데이터 |
| 2 | 서비스 미션 |
| 3 | 로그인 미션 |
| 4 | 해시·복구 미션 |
| 5 | 튜토리얼·힌트·저장·초기화 |
| 6 | 입문자 시연·오류 수정·제출 |

입력 처리·외부 요청 없음·정상 기능 유지·해시·저장·초기화를 자동 검사합니다. 입문자 3–5명에게 소요 시간, 막힌 행동, 포트와 해시의 의미 설명을 확인합니다. 제출물은 소스·실행 파일·검증 기록·3–5분 시연 영상입니다. 추가 서비스 비용 목표는 0원입니다.

## 후속 범위

필수 미션 안정화 후 선택 퍼즐을 검토합니다. 실제 서버 실습은 내부 전용 VM의 앱 1개·미션 1개로 제한하고, 외부 노출·개인 자료 없이 복원과 자원 제한을 확인합니다. 장난감 암호는 실사용 보호 방식으로 소개하지 않습니다.
