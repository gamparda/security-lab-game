# Windows 3D 실습실 통합 계획

작성일: 2026-10-04 · 상태: 계획안

- 대상: [PR #15](https://github.com/nu4ddi4/security-lab-game/pull/15), `14d4305`.
- 기준: Windows 배포판 v0.3.0, main `f3a57b4`. PR의 작업 기준은 v0.2.8 시점의 `b012e7a`다.
- 권장 배포: Windows 10/11 x64, 새 기능 버전 `v0.4.0`. 실행 방식은 기존 단일 EXE와 포터블 ZIP을 유지한다.

## 1. 도입 판단

**3D 실습실은 받아들일 만하다. 첫 통합은 2D 기본 화면과 선택형 3D로 진행한다.**

| 판단 항목 | 근거와 조건 |
| --- | --- |
| 학습 목표 | 서버랙·관리 PC·자료 보관함을 기존 도구와 연결해 조사 대상의 관계를 공간으로 보여준다. 조사 → 설명 → 방어 → 정상 기능 재검증은 그대로 유지한다. |
| 구현 적합성 | 기존 엔진을 중심으로 읽기 전용 상태와 도구 열기 요청을 연결한다. 이동·장비 선택이 명령 실행, 단서 지급, 점수 지급을 대신하지 않는다. |
| Windows 배포 | GLB와 Three.js를 EXE에 포함할 수 있다. 사용자에게 Python·Node.js·Blender·소스 폴더 설치를 요구하지 않는다. 기존 설치된 브라우저를 사용한다. |
| 운영 부담 | 모델은 약 4.16MB이며 외부 다운로드 없이 실행한다. 3D 성능·그래픽 오류·추가 자산 관리 비용은 발생한다. |
| 남은 검증 | 교육 효과와 학교 PC 적합성은 미검증이다. RTX 5060 Ti의 60FPS 관측을 전체 Windows PC의 성능 보장으로 사용하지 않는다. |

첫 실행은 기존 2D 화면으로 시작하고 사용자가 3D를 선택하면 다음 실행에도 선택을 기억한다. WebGL 미지원·복구 실패 시에는 2D로 이어간다. 입문자 시연과 학교 PC 검증을 통과한 뒤 데스크톱 기본 화면을 3D로 바꿀지 결정한다.

이번 통합은 기존 미션의 표현과 접근 방식을 확장한다. 새 미션·실제 서버 접속·추가 점수 체계는 후속 작업으로 둔다.

## 3. 통합 구조와 첫 실행

게임 상태·저장·완료 판정의 담당은 기존 app/engine/storage로 유지한다. 3D는 상태를 표시하고 허용된 도구를 연다.

- `labbridge`는 미션 ID·제목·단계·점수·다음 행동·처리 중 상태를 읽기 전용으로 전달한다. 장비 연결은 숫자 인덱스 대신 미션 ID를 사용한다.
- 보기 선택은 게임 저장과 다른 키로 보관한다. 2D↔3D 전환, 위치 복귀, 모델 재시도는 미션 진행을 바꾸지 않는다.
- 진행 보존은 같은 브라우저·프로필·접속 주소를 기준으로 한다. 주소가 달라지면 기존 내보내기/가져오기를 사용한다.
- 3D 오류는 별도 안내 영역에서 표시한다. 저장 실패·충돌·해시 재시도 안내를 덮어쓰지 않는다.
- 도구 창 안에서 기존 다음 행동·저장 이동·초기화·결과 화면을 모두 사용할 수 있게 한다. 가져오기/초기화 대화상자가 열리면 해당 대화상자가 키보드와 Escape를 우선 처리한다.
- 3D CSS와 무거운 모듈은 선택 진입 시 준비한다. 사용자가 3D를 선택하지 않은 첫 실행에서 추가 자산이 기존 화면 표시를 지연시키지 않게 한다.

첫 실행 순서는 **필수 파일 준비 → 기존 시작 감시와 CSS 적용 → 저장 복원 → 2D 화면 준비 → 사용자 선택 시 3D 준비**다.

3D 준비는 모듈·CSS·모델·그래픽 준비까지 제한 시간을 적용한다. 초기 기준은 20초이며, 준비 중에도 2D 이어하기를 사용할 수 있다. 실제 첫 프레임을 표시하기 전에는 탐색 버튼을 활성화하지 않는다. 취소된 시도의 늦은 응답으로 3D가 다시 열리지 않게 한다.

WebGL 손실 시에는 이동과 탐색을 중지하고 복원을 확인한다. 재시도에서 렌더러를 재생성할 경우 기존 GPU 자원·입력 이벤트·프레임 반복을 정리한다. 복구되지 않으면 탐색을 허용하지 않고 2D를 유지한다. Pointer Lock 거부도 재시도와 2D 선택으로 처리한다.

### 자산·CSP·패키징 세부 기준

- 공개 목록은 필요한 정확한 파일명만 허용한다. 3D JS/CSS·GLB·Three.js 의존 모듈을 포함하고 제작용 JPG·통계·소스 스크립트는 공개하지 않는다.
- 필수 2D 자산은 시작 전에 검증한다. app가 정적으로 가져오는 `labbridge.js`도 필수다. 선택 3D 자산을 읽지 못하면 원인을 기록하고 GET/HEAD 요청에 404를 반환해 2D가 실행될 수 있게 한다. 배포 검사는 선택 자산까지 모두 포함되어야 통과한다.
- HTML 메타·Python·Node 서버의 CSP를 맞춘다. 시작 감시의 해시를 보존하고, 변경하면 다시 계산한다. 모델과 내장 텍스처에 필요한 self/blob 허용만 추가한다. `unsafe-inline`·`unsafe-eval`은 허용하지 않는다.
- 모든 실행 자산을 PyInstaller EXE에 넣는다. vendor 재현성 검사 후 패키징한다. 사용자 실행 시 npm·CDN·Blender를 사용하지 않는다.
- main의 `launcher.py`·`instance.py`와 사용자별 잠금·선호 포트·오류 복사 기능을 유지한다. 시작 진단은 필수 준비, 선택 3D 자산 상태, 오류 원인을 구분한다.
- PR의 정리 경로 검사와 `-LiteralPath`는 Windows 검사에 반영한다. 실제 창 표시 확인을 약화시키는 숨김 실행은 그대로 적용하지 않는다.
- Three.js MIT 라이선스와 Poly Haven CC0 출처를 보존한다. README·릴리즈 설명은 실행 방법과 변경점 위주로 짧게 작성한다.

### 자동 검증과 실제 PC 검증 구분

- CI의 2D 회귀는 기존 Chromium PC/모바일·Firefox·WebKit에서 유지한다. 3D 기능 검사는 지원이 확인된 Chromium에서 실행하고, 미지원 환경은 2D 전환을 검증한다.
- main의 `test`와 Windows PR 패키징 job을 유지한다. Windows EXE 빌드·실행 검사가 통합 PR에서도 자동 실행되도록 확인한다.
- `npm run check`의 서버 검사는 PR의 `scripts/test-server.js`처럼 Windows에서 `python`, 다른 환경에서 `python3`를 사용하도록 합친다. Playwright의 개발 서버 실행도 같은 기준을 적용한다.
- Windows 우선 브라우저는 Edge와 Chrome이다. 다른 기본 브라우저에서 3D를 지원하지 않아도 2D를 사용할 수 있어야 한다. Chromium 실행 경로·D3D11 옵션을 Firefox/WebKit에 넘기지 않는다.
- Linux 소프트웨어 렌더링과 Windows hosted runner 검사는 기능 확인에 사용한다. D3D11 옵션만으로 실제 GPU 사용을 가정하지 않는다. 테스트 제한 시간은 측정에 맞춰 정하되 충돌 판정 오류를 시간 증가로 감추지 않는다.
- 실제 Windows 10/11의 내장 GPU PC와 외장 GPU PC에서 Edge/Chrome을 확인한다. 브라우저 버전·GPU·가속 여부·해상도·EXE 버전·로딩 시간·FPS를 기록한다.
- 첫 품질 목표는 대표 내장 GPU PC의 1080p 실습실 보행에서 평균 30FPS 이상이다. 2분 보행과 도구 전환을 측정하며 도구 창 정지 시간은 제외한다. 미달하면 그림자·픽셀 비율을 낮춰 다시 확인한다. 이는 검증할 목표이며 현재 보장 수치가 아니다.
- 가속 비활성·그래픽 미지원 환경에서도 2D 전환과 저장은 정상이어야 한다. 30분 실행과 3D 재시도·보기 전환 반복으로 자원 누적과 조작 중단을 확인한다.

입문자 3–5명 시연에서는 전체 시간, 장비/도구를 찾다가 막힌 행동, 2D 전환 이유, 포트·해시 의미 설명을 기록한다. 실제 PC·접근성·입문자 검증은 후속 작업이며 이번 배포에서 완료를 주장하지 않는다. 결과를 얻기 전에는 2D 기본 화면과 선택형 3D를 유지한다.

## 6. 릴리즈와 복구

- `package.json`·`package-lock.json`·`docs/RELEASE.md`를 새 버전에 맞춘다. 기존 자동 릴리즈는 버전 증가와 RELEASE 문서 변경을 기준으로 동작한다.
- 보호된 main에 통합하기 전 `test`와 Windows 패키징 검사 결과를 모두 확인한다. 최신 main과 통합된 최종 커밋에서 Windows EXE를 다시 빌드하고 검사한다.
- 릴리즈 제목은 `Security Lab v0.4.0`. 자산은 `SecurityLab-v0.4.0-Windows-x64.exe`, 같은 이름의 ZIP, `SHA256SUMS-v0.4.0.txt`로 구성한다.
- ZIP에는 동일한 EXE 하나만 넣는다. 단일 EXE와 ZIP 내부 EXE의 바이트 일치와 SHA-256을 확인한다. 웹 ZIP과 가이드는 배포 자산에 추가하지 않는다.
- 그래픽 문제는 우선 2D 이어하기로 복구한다. 진행 유실·EXE 실행 차단·2D 사용 불가가 나오면 새 게시를 보류한다. 게시 후 발견하면 저장 키를 유지한 수정 버전으로 처리한다.
- v0.2.x 또는 PR의 구 저장 코드는 v2 저장을 읽지 못하고 오래된 v1 진행을 표시할 수 있다. 버전을 되돌릴 경우 진행을 먼저 내보내고 호환성을 확인한다. 안정판 main v0.3.0은 v2 저장을 지원한다.
