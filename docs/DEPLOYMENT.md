# 로컬 웹앱과 홈서버 배포

## 지금: Windows 포터블 로컬 웹앱

`SecurityLab.exe`를 실행하면 내장 Python 런타임이 `127.0.0.1`에 정적 서버를 열고 기본 브라우저를 자동으로 실행합니다. 서버는 게임 파일만 읽어서 제공하며 게임 입력을 처리하는 API는 없습니다. 패키지 설치나 관리자 권한이 필요 없습니다.

Windows 10/11 64비트를 대상으로 합니다. 실행 창의 「게임 다시 열기」와 「종료」 버튼으로 조작합니다. 기본 포트는 5173이고 사용 중이면 5183까지 빈 포트를 찾습니다. 여러 실행 창을 동시에 열면 다른 포트·저장 공간을 사용할 수 있으므로 기존 실행 창에서 게임을 다시 여는 것을 권장합니다.

브라우저 자동 열기 전에는 모든 허용 게임 파일의 로컬 HTTP 응답·형식·내용을 검사합니다. 브라우저에서는 CSS 적용과 모듈 초기화·진행 복원이 완료된 뒤 게임을 표시합니다. CSS가 늦거나 로딩에 실패해도 스타일 없는 게임을 바로 보여주지 않으며, 자동 재시도 후 실패하면 다시 불러오기를 안내합니다.

브라우저와 출처(주소·포트)별 localStorage에 진행을 저장합니다. 실행 파일 이동은 가능하지만 세이브 데이터가 실행 파일과 함께 이동하지는 않습니다. Python·Node·npm은 빌드 및 개발 환경에만 필요합니다.

## 나중: 같은 웹 파일을 홈서버로 배포

1. `python scripts/export_web.py` 또는 Windows 패키징 워크플로로 `security-lab-web.zip`을 생성합니다.
2. ZIP을 홈서버의 정적 웹 디렉터리에 압축 해제합니다. 내용은 `index.html`, `src/`의 게임 파일뿐입니다.
3. 기존 정적 웹 서버로 제공합니다. Nginx 구성 예시는 `deploy/nginx.conf`입니다. 웹 루트는 서버의 실제 경로에 맞춥니다.
4. 홈서버의 리버스 프록시에 도메인과 HTTPS 인증서를 설정합니다. Web Crypto SHA-256에는 HTTPS가 필요합니다. `localhost` 예외는 다른 기기에서 홈서버 IP로 접속할 때 적용되지 않습니다.
5. 새 주소에서 튜토리얼과 세 미션을 플레이하고 해시 계산·새로고침 후 저장·외부 요청이 없는지 확인합니다.

홈서버에서도 런처·Python·Node·DB 없이 정적 파일로 동작합니다. 실제 호스팅은 아직 배포하지 않았습니다. 서버 환경과 HTTPS 설정을 확인한 뒤 진행합니다. 로컬 앱의 세이브는 홈서버 주소로 자동 이전되지 않습니다.

## 배포 형태 선택

첫 버전은 포터블 `.exe`를 제공합니다. `.exe`는 파일 형식이고 포터블/설치형은 배포 방식이므로 포터블도 `.exe`일 수 있습니다. 설치형은 시작 메뉴 등록·제거·자동 업데이트가 필요해질 때 추가합니다. `.deb`는 Ubuntu/Debian 설치 패키지이므로 Windows 버전에는 사용하지 않습니다.
